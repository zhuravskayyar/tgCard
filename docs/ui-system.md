# Єдина система UI Cardastika

Локальна уніфікація, 06.09.2026. Збережено Dark Clean Fantasy, існуючі
дерев’яні/металеві assets, храмові й пергаментні акценти та структуру екранів.
Backend, API, база, економіка, маршрути та правила гри не змінювалися.

## Джерела стилів

Порядок підключення визначено в `client/src/main.tsx`:

| Файл у `client/src/styles/` | Відповідальність |
| --- | --- |
| `global.css` | Наявна композиція екранів, артові сцени, анімації й спеціальні стани карт |
| `tokens.css` | Єдина палітра, шрифти, розміри, відступи, матеріали, тіні |
| `controls.css` | Основні/другорядні/небезпечні/успішні дії, disabled, малі й іконкові кнопки, вкладки |
| `surfaces.css` | Звичайні панелі, рядки, модальні поверхні |
| `typography.css` | Заголовки, допоміжний текст, форми, читабельність та адаптивні уточнення |
| `menu.css` | Один MenuRow, його компактний варіант і наявні адаптери рядків кампанії/поглинання |
| `shell.css` | Один TopHud і BottomNav для всіх екранів |

`guild.css` і `guild-polish.css` залишаються для композиції гільдії й її
спеціальних сцен. Окремого варіанта глобальної оболонки для гільдії немає.
Не додавати нову тему через `.app-shell:has(.some-screen)`.

## Правила використання

- Для навігаційних рядків використовувати `MenuRow`. Металева текстура є
  стандартною; `compact` змінює висоту з 60 до 52 px, зберігаючи іконки й текст.
  Три частини наявної текстури зберігають пропорції її торців. Друга CSS-рамка
  поверх рамки asset не додається.
- Нові кнопки використовують `ui-button` та за потреби `ui-button--primary`,
  `ui-button--danger`, `ui-button--success`, `ui-button--small`, `ui-button--icon`.
  Базовий `ui-button` — secondary. Неактивність задається справжнім `disabled`
  або чинним `aria-disabled`, а не лише кольором. Малі кнопки мають компактніший
  текст/відступи, але зберігають 44 px для натискання.
- Наявні класи кнопок є явними CSS-аліасами тієї самої системи. Це дозволило
  зберегти обробники подій і JSX екранів без масового рефакторингу.
- Для нових звичайних поверхонь є `ui-panel` і `ui-dialog`; для вкладок —
  `ui-tab` з `aria-selected`. Спеціальні карткові FX і предметні rarity-акценти
  залишаються локальними, оскільки позначають зміст, а не іншу тему.
- Палітра: темний теплий камінь, дерево, бронза. Кольори стихій — окремі tokens;
  вони не використовуються як загальна синьо-бірюзова тема екрана.
- Радіуси звичайних поверхонь: 4/6/8 px. Круглі аватари, індикатори та
  геометрія artwork мають функціональні винятки.
- Текст: `font-display` для назв, `font-label`/`font-body` для UI,
  `font-number` для чисел. Числові значення не скорочуються заради верстки.
  Пергаментні заголовки мають окремий темний `text-on-parchment`.
- HUD: 62 px + safe area; BottomNav: 68 px + safe area; максимальна ширина
  оболонки 430 px. Між ними прокручується `app-content`.
- `TopHud` використовує чинні авторизовані дані. BottomNav містить тільки
  «Головна», «Профіль», «Гільдія». Переходи й поведінка не змінені.
- `EquipmentArt` не малює іконку порожнього слота і типово не додає element badge.
  Доступна назва слота залишається в `aria-label`. Наявні sprites предметів
  і CSS-позначення рідкості збережено.
- Замість emoji в бойових/навчальних індикаторах використовуються SVG з
  `AppIcon`; чотири чинні elemental SVG не замінено.

## Перевірки та межі

Локально запущено Vite на `http://127.0.0.1:5173`, API на порту 3000 та
PostgreSQL у WSL з доступом через `127.0.0.1:5432`. Перевірки виконуються
з реальним локальним `dev_leader`, його колодою та гільдією; UI mock-даних немає.

Мобільні перевірки: 360, 390 і приблизно 425 CSS px (браузер округлює останню
ширину до 426). Знімки й вимірювання — `.runtime/ui-unification/`.
Перевіряються один HUD/BottomNav, три навігаційні дії, справжні ім’я/рівень/
валюти, горизонтальне переповнення, обрізання тексту, зображення та touch targets.

`npm run build --workspace client` включає TypeScript і production Vite build.
Клієнт не має окремого test script. Backend/game-core test suite не запускався:
правки презентаційні; функціональні переходи й UI-стани перевіряються браузером.
Збірка попереджає про JS chunk понад 500 kB. Сервер має попередження `pg` про
одночасні `client.query()`; серверні файли в цьому проході не змінювалися.

**Telegram acceptance залишається заблокованим конфігурацією публічного URL.**
Активна menu URL — `https://app.cardastika.org/?v=d00a3f684880`.
HTML Cardastika та `/api/health` відповідають 200, але це інша публічна збірка:
на `/api/dev/accounts` публічно 404, локально 200 і 7 акаунтів.
Зв’язок цього публічного `/api` з поточним локальним сервером не підтверджений.
Telegram Desktop не запущений; авторизований запуск локальних змін усередині
Telegram не підтверджений. Не видавати локальні перевірки за Telegram acceptance.
Bot menu, production-конфігурація, push і deployment не змінювалися.
